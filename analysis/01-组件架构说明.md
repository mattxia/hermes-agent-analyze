# Hermes Agent 组件架构说明

## 项目概述

Hermes Agent 是一个由 Nous Research 构建的**自我改进型 AI 代理**。它拥有内置学习循环——从经验中创建技能、在使用过程中改进技能、搜索过往对话、跨会话构建用户画像。可运行于 CLI、消息网关（Telegram/Discord/Slack 等）、TUI、Electron 桌面应用，以及 ACP/MCP 服务器模式。

## 各组件功能介绍

### 1. 用户交互层 — 多入口统一接入

| 组件 | 文件位置 | 功能 |
|------|---------|------|
| **CLI/TUI** | cli.py | 基于 prompt_toolkit 的交互式终端界面，支持多行编辑、斜杠命令自动补全、会话历史、中断重定向、流式工具输出 |
| **消息网关** | gateway/run.py | 启动所有已配置平台适配器的网关进程，管理 AIAgent 缓存池（LRU + 空闲 TTL 淘汰），处理流式事件分发 |
| **桌面应用** | apps/desktop | React + Electron 桌面应用，包含聊天界面、Dashboard、桌面宠物（Pet）覆盖层 |
| **ACP 服务器** | acp_adapter/server.py | 通过 Agent Client Protocol 暴露 Hermes，实现编辑器（Zed 等）集成 |
| **MCP 服务器** | mcp_serve.py | 将消息会话作为 MCP 工具暴露，允许 Claude Code / Cursor / Codex 等 MCP 客户端列出会话、读取消息、发送消息、轮询事件 |

### 2. CLI 命令层 — hermes_cli/

`hermes` 命令的命令分发与子命令实现：

| 组件 | 功能 |
|------|------|
| hermes_cli/main.py | CLI 主入口，解析参数并分发到各子命令 |
| hermes_cli/config.py | 配置文件读写（config.yaml），环境变量展开 |
| hermes_cli/setup.py | 交互式设置向导，配置 provider/tools/gateway |
| hermes_cli/gateway.py | 网关服务管理（start/stop/status/install） |
| hermes_cli/models.py | 模型/provider 选择与切换 |
| hermes_cli/mcp_catalog.py | 外部 MCP 服务器注册目录管理 |
| hermes_cli/skills_hub.py | Skills Hub — GitHub App 认证的技能市场 |

### 3. 代理核心引擎 — run_agent.py + agent/

这是整个系统的**核心窄腰**，所有入口最终都汇聚到 `AIAgent` 类：

| 组件 | 文件 | 功能 |
|------|------|------|
| **AIAgent** | run_agent.py | 核心代理类，管理 LLM 客户端、工具 schema、会话状态、prompt cache |
| **会话循环** | agent/conversation_loop.py | ~3900 行的 `run_conversation` 主体：模型调用 → 工具派发 → 重试/回退 → 压缩 → 后台审查触发 |
| **系统提示词** | agent/system_prompt.py | 三层提示词组装：`stable`（身份+工具指引+技能）、`context`（上下文文件）、`volatile`（记忆+时间戳）。每会话构建一次，保持 prefix cache 温热 |
| **工具执行** | agent/tool_executor.py | 顺序与并发工具调用派发，含预算控制（大上下文模型保留 100K/200K，小模型按比例缩放） |
| **上下文压缩** | agent/context_compressor.py | 默认上下文引擎实现：使用辅助模型摘要中间轮次，保护首尾上下文，迭代式摘要更新 |
| **上下文引擎基类** | agent/context_engine.py | 可插拔上下文引擎抽象基类，第三方引擎（如 LCM）可通过插件替换 |
| **记忆管理** | agent/memory_manager.py | 记忆提供者编排器，单集成点。只允许一个外部插件提供者，防止工具 schema 膨胀 |
| **后台审查** | agent/background_review.py | 每轮结束后 fork 代理自身，评估"是否应保存/更新技能或记忆"。继承父代理的 prefix cache，工具白名单限制为记忆+技能管理 |
| **技能策展** | agent/curator.py | 后台技能维护：基于活动时间戳自动转换生命周期状态，fork 辅助代理执行 pin/archive/consolidate/patch。只归档不删除，pinned 技能豁免 |
| **辅助客户端** | agent/auxiliary_client.py | 廉价/快速模型客户端，用于摘要、标题生成等非主会话任务 |
| **单次调用** | agent/oneshot.py | 无状态单次 LLM 请求，用于 commit 消息生成、重命名建议等小任务，不污染会话历史 |
| **混合代理** | agent/moa_loop.py | Mixture-of-Agents 运行时，在模型迭代前收集参考模型上下文 |
| **子代理委派** | tools/delegate_tool.py | 生成隔离的子 AIAgent 实例，独立上下文+受限工具集+独立终端会话。支持批量并行模式 |

### 4. 工具系统 — tools/

采用**自注册模式**：每个工具文件在模块级别调用 `registry.register()` 声明其 schema、handler、toolset 归属和可用性检查。

| 工具类别 | 代表文件 | 功能 |
|---------|---------|------|
| **工具注册** | tools/registry.py | 中央注册表，AST 扫描自动发现内置工具模块 |
| **终端执行** | tools/terminal_tool.py | Shell 命令执行，支持 6 种后端（local/Docker/SSH/Singularity/Modal/Daytona） |
| **文件操作** | tools/file_tools.py | 文件读写、编辑、搜索（含路径安全检查） |
| **网页搜索** | tools/web_tools.py | 网页搜索与抓取 |
| **浏览器自动化** | tools/browser_tool.py | 浏览器控制（CDP/CamoFox） |
| **技能管理** | tools/skills_tool.py | 技能列表与查看，渐进式披露架构 |
| **MCP 集成** | tools/mcp_tool.py | 外部 MCP 服务器工具桥接 |
| **记忆工具** | tools/memory_tool.py | 记忆读写操作 |
| **媒体生成** | tools/image_generation_tool.py | 图像/视频生成（FAL 等后端） |
| **消息发送** | tools/send_message_tool.py | 跨平台消息投递 |

### 5. 模型提供商抽象 — providers/ + agent/transports/

**双层抽象**，将"提供商是谁"和"如何与之通信"分离：

| 组件 | 文件 | 功能 |
|------|------|------|
| **ProviderProfile** | providers/base.py | 声明式提供商画像：认证、端点、客户端特性、请求时特性。不含客户端构造/流式/凭据轮换 |
| **ProviderTransport** | agent/transports/base.py | 传输层抽象：`convert_messages → convert_tools → build_kwargs → normalize_response`。每个 api_mode 一个实现 |
| **Bedrock Transport** | agent/transports/bedrock.py | AWS Bedrock 格式转换 |
| **Codex Transport** | agent/transports/codex.py | Codex/Responses API 格式转换 |

### 6. 消息网关层 — gateway/

将代理能力延伸到 20+ 消息平台：

| 组件 | 功能 |

| gateway/stream_dispatch.py | 流式事件路由：代理发出类型化事件，适配器决定如何渲染投递 |

| gateway/slash_commands.py | 跨平台斜杠命令处理 |
| gateway/pairing.py | 平台配对认证 |
| gateway/scale_to_zero.py | 空闲缩容到零 |

| 组件 | 文件 | 功能 |

### 8. 扩展生态层

| 组件 | 功能 |
|------|------|
| **插件系统** (plugins/) | 插件机制扩展代理能力。内置：Google Meet 集成、Spotify 控制、Honcho 记忆、Exa/xAI 网页搜索 |

## 核心设计原则

1. **每会话 prompt cache 神圣不可侵犯** — 长会话每轮复用缓存前缀，任何修改历史上下文/切换工具集/重建系统提示的操作都会使缓存失效。唯一例外是上下文压缩。

2. **核心是窄腰，能力在边缘** — 每个模型工具随每次 API 调用发送，新增核心工具门槛极高。新能力应优先通过 CLI 命令+技能 → 服务门控工具 → 插件 → MCP 服务器 → 核心工具（最后手段）的阶梯接入。

3. **自我改进闭环** — 后台审查 fork 评估每轮对话 → 自动创建/更新技能 → Curator 定期维护技能集合 → 跨会话搜索（FTS5）+ 用户画像建模。
